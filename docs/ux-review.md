## 1. 画面遷移の現状

```
                    ┌─────────────── 上部タブ ───────────────┐
                    ホーム          コレクション        設定
                     │                │                 │
   ┌── 植物未選択 ──┤                ├ 額装作品の壁     ├ 歩数計開始/同期
   │  種選択リスト   │                │  └ 拡大鑑賞      ├ 週間振り返り
   │   └ 開花プレビュー              │     (ドラッグ回転) ├ 環境音 on/off
   │      └「この種を育てる」         └ 図鑑「名画の由来」 └ リセット
   │                │
   └── 植物選択済 ──┤
       3Dシーン(没入) ├ 「眺める」→ 鑑賞モード (Esc/タップで解除)
       進捗ライン     ├ 水面タップ→波紋 / 傾き視差
                     └ 開花完了 → 点灯式 → 完成プレート
                          └「額装を選ぶ」→ [名前入力(初回)] → 額縁選択モーダル
                             └「この額装で飾る」→ コレクションへ収蔵
                                └ ホームに「次の作品を選ぶ」

   ※ grow-view（歩数同期・歩数計・成長確認ボタンを持つ育成画面）は
     どこからも到達できない（G-1）
```

物語の弧（育てている間は生きた庭 → 完成したら美術館へ）と画面構成は一致しており、幹となるフロー自体は健全。問題は「毎日の入口」と「モーダルの出口」に集中している（§2）。

## 2. 指摘一覧（重要度順）

### 重要度 A — コア体験を損なうもの

| ID | 指摘 | 詳細 | 根拠 |
|---|---|---|---|
| U-1 | **毎日のコアループに「歩数の入口」がない** | 本番のホームには歩数を反映する操作が一切なく、歩数計の開始・同期ボタンは**設定タブの奥**にしかない（該当ボタン群を持つ grow-view は到達不能 = G-1）。ネイティブブリッジが無いWeb版では、ユーザーは「開く→設定→歩数計を開始」を毎回辿らないと植物が育たない。「開くだけで庭が育っている」という約束（FR-2）と導線が噛み合っていない | app.js renderHome（歩数操作なし）、index.html:150-166（設定内の同期UI） |
| U-2 | **名前入力モーダルに出口がない** | `name-entry-modal` は閉じるボタンが無く、`required` 入力のため**名前を入れない限り額装に進めも戻りもできない**。「プレートに刻む名前」という情緒的な位置づけに対し、強制はトーンに反する。Esc・背景クリックも効かない → **対応済み（2026-07-10）**: 閉じるボタン（×）とEscで中断できるようにした（額装は完成プレートからいつでも再開可能） | index.html:228-239、app.js の close 処理なし |
| U-3 | **モーダルの作法が4種でバラバラ** | 額縁選択=×とEscのみ / 拡大鑑賞=背景クリック可 / 週間振り返り=×のみ（Esc不可）/ 名前入力=出口なし。さらに**全モーダルで背景スクロールロックが無い**（鑑賞モードのみ実装済み）。加えて額縁選択モーダル(z-index:20)とPC時の固定タブバー(z-index:20)が同値で、タブバーがモーダルに被る可能性 | styles.css:2195,1874、app.js:1083-1176 |

## 3. 良い点（維持すべき設計）

- **点灯式の演出構造**（暗転0.45s→スポットライト→2.6s後にプレート→4sで平常）: 「達成の瞬間を美術館の文法で祝う」というコンセプトの核が実装として成立している。スポット中心を花頭のNDC位置に合わせる芸の細かさも良い
- **種選択の2段階**（カード→開花プレビュー→決定）: 開花後の姿を先に見せることで「60,000歩の目標」に絵が付く
- **focus-visible の金リング**が主要導線に整備済み。キーボード/スイッチ操作への配慮が既にある
- **safe-area対応の網羅性**（ホームインジケータ回避が浮遊ボタン全てに入っている）
- **名前入力のタイミング**（初回額装の直前）: 意味が生まれる瞬間に聞く設計は正しい。問題は出口がないことだけ（U-2）
- **daily-copy の `pointer-events:none`**: コピー帯が背後の水面タップを妨げない
- 図鑑「名画の由来」が収蔵数に応じて増える構造: 収集の報酬が「教養」であるのはこのアプリらしい

## 5. 改善案 — 構造・仕様の変更が必要なもの

いずれも「どうするか」の決定が先。実装前に方針確認を推奨。

### 5.1 歩数の入口（U-1、最優先）

方針案（排他ではない）:
1. **ホームの没入シーンに最小限の歩数アクションを1つ置く**。例: 進捗ライン（タブバー直上）をタップ可能にし、「歩数を確認」= ブリッジ同期→なければ歩数計開始の提案、を1タップで行う。没入原則を守るため常設ボタンは増やさない
2. **起動時の自動同期**: ブリッジがあれば `init()` で自動同期（現在は手動のみ）。DeviceMotion は権限が必要なので、初回に一度許可されたら次回以降は起動時に自動再開を試みる
3. grow-view は**廃止して削除**（機能はホーム＋設定に既に分散済み。残すと二重管理になる）— A-2 と同じ結論

### 5.2 モーダルの共通作法（U-2, U-3, U-12）

「Artariumのモーダルはこう振る舞う」を1つ決めて全モーダルへ適用する:
- Escで閉じる / 背景クリックで閉じる（確定操作を失わない範囲で）/ 表示中は背景スクロールロック
- 名前入力のみ例外扱いにせず、**「あとで決める」の逃げ道**を付ける（スキップ時は「作者名なし」で額装し、設定から後で入力できる = requirements.md S-1 とセット）
- 実装は共通の openModal/closeModal ヘルパーに寄せる（architecture.md §8.2 のビュー分割と相性が良い）

### 5.3 横向き・小画面（U-7）

- 短期: `@media (orientation: landscape) and (max-height: 500px)` で絶対配置ボタン群の退避レイアウトを用意
- または portrait 前提を明示する（manifest は既に `portrait` 指定なので、Web表示でも「縦向きでお楽しみください」の案内を出す選択もある。工数最小）

### 5.4 機能の可発見性（U-12, U-13）

- 週間振り返り: 日曜の自動表示に加え、ホームの進捗ラインのロングタップ/タップメニューから開けると「歩数まわりは進捗ラインに集まっている」という一貫した心的モデルになる（5.1と同じ場所）
- PWAインストール: 初回の額装完了直後（感情のピーク）に一度だけ、美術館の文体で控えめに提案

## 6. 対応の推奨順序

1. **§4 の一括修正**（CSS/文言のみ、半日以内の粒度）
2. **U-2 名前入力の逃げ道**（トラップ解消は単独でも価値が高い）
3. **5.1 歩数の入口**（コアループの成立。M-3 の歩数取得方針とセットで決める）
4. **5.2 モーダル共通化**（app.js 分割 = architecture.md §8.2 の最初の題材にすると一石二鳥）
5. 5.3 / 5.4 は上記の後で

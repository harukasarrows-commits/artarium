Artarium 今後の開発計画

最終更新: 2026-07-10

更新ルール

今後、新しい機能を追加する、優先順位を変える、実装済みにする、不要になった機能を削除する場合は、この資料を更新する。 仕様として確定した内容は specification.md に反映する。 実装手順や作業ルールが必要な内容は development-instructions.md に反映する。 実装とのズレの監査結果（2026-07-10）は requirements.md / architecture.md / ux-review.md を参照する。

開発方針

Artarium は、まずWebプロトタイプで体験と見た目を固め、その後スマホアプリ化する。 初期リリースでは植物を10種類程度用意する方針。

優先すること:

  • 植物が美しく見えること
  • 歩いて育つ体験が分かりやすいこと
  • コレクションに収蔵する流れが気持ちいいこと
  • モデル追加や調整が簡単にできること
  • スマホアプリ化しやすい構造にしておくこと
  • 無料でも体験が成立し、追加植物や額縁で自然に課金できること

避けること:

  • 画面に情報を出しすぎる
  • ゲームっぽく派手にしすぎる
  • モデルごとの設定が混ざる
  • 後から植物を追加しにくい構成にする
  • 成長速度を強く課金で買わせる設計にする
  • 鑑賞体験を広告で邪魔する

対象ユーザー

主な対象:

  • 美術館、アート、名画が好きな人
  • 歩く習慣を楽しく続けたい人
  • 落ち着いた育成・収集アプリが好きな人
  • 植物、花、インテリアが好きな人
  • 健康管理アプリの数字だけでは続きにくい人

想定:

  • 20代後半から50代
  • アートや生活雑貨が好きな層
  • 強いゲーム性より、静かな達成感を求める層

1. 植物モデルの整備

目的: 各植物の Stage1 から Stage6 までを、見た目の成長が自然に分かるように整える。

やること:

  • 各植物の6段階GLBを用意する
  • モデルのサイズ、位置、角度をデモ版で調整する
  • 土台との接地感を調整する
  • 水面植物は水面と反射の見え方を調整する
  • 設定を本番へ反映する

対象（2026-07-10 時点: 9種すべて6ステージのGLB配置・配置値の焼き込みが完了。微調整は継続）:

  • The Scream Bloom / Sunflower Bloom / Water Lily Bloom / Aquatic Bloom / Renaissance Smile Bloom
  • Nocturne Sky Bloom / Golden Embrace Bloom / Monochrome Fracture Bloom / Pearl Light Bloom（2026-07 追加）
  • 追加植物 1種類程度（10種目）

初期リリース目標:

  • 合計10種類程度
  • 各植物6ステージ
  • 合計約60モデル（現在54モデル配置済み）

2. 土台タイプの確定

目的: 植物ごとに「土から生える」「水面から生える」などの表現を決める。

やること:

  • gallery-loam の見た目を確定する
  • water-surface の見た目を確定する
  • 植物ごとの soilType を確定する
  • 新しい土台タイプが必要か検討する

候補:

  • 土の丘
  • 水面
  • 石の台座
  • 砂地
  • 苔の台座

3. 額縁選択体験の完成度向上

目的: 開花後に「作品になった」感覚を強める。

やること:

  • 額縁選択画面の見た目を整える
  • 額縁候補に開花植物を正しく表示する
  • 植物が額縁から飛び出しすぎないように調整する
  • 額縁GLBを追加する
  • 額装後のコレクション表示を整える

現在:

  • 背景選択は無効
  • 額縁のみ選択可能
  • 額縁GLBがない場合はCSSフォールバック

4. コレクション画面の鑑賞体験改善

目的: ただの一覧ではなく、小さな美術館の展示として見せる。

やること:

  • 額装作品を大きく見せる
  • 作品名を見やすくする
  • 説明文は短く控えめにする
  • 実在作家名を表示しない
  • ユーザー名を作者として表示するか検討する
  • 作品をタップした時の詳細表示を検討する

優先度 中

5. ユーザー名の反映 → 対応済み（2026-07-10）

目的: アプリ開始時に入力した名前を、作品の作者欄などに反映する。

やること:

  • ~~初回額装前の名前入力~~ → 実装済み（スキップ可）
  • ~~コレクションの作者欄にユーザー名を出す~~ → 実装済み
  • ~~設定画面から名前変更できるようにする~~ → 実装済み（作者名行をタップ）

注意:

  • 例文に特定の個人名を出さない

6. 歩数連携の実装方針整理

目的: スマホアプリ化に向けて、歩数取得の実装方法を決める。

やること:

  • iOS HealthKit の実装方針を決める
  • Android Health Connect の実装方針を決める
  • Expoで実装するか、ネイティブモジュールを使うか検討する
  • 歩数取得できない場合の代替導線を決める

現在のWeb版:

  • ネイティブブリッジ想定
  • DeviceMotionによる簡易検知
  • 開発用テスト加算

7. スマホアプリ化準備

目的: Web版で固めた体験を、React Native / Expo に移行しやすくする。

やること:

  • 画面構成をReact Native前提で整理する
  • localStorage を AsyncStorage に置き換えやすくする
  • 3D表示ライブラリ候補を決める
  • GLBモデルの読み込み方法を検証する
  • PWAとネイティブアプリで共通化できるデータを整理する

8. モデル管理ルールの整理

目的: モデルが増えても迷わないようにする。

やること:

  • ファイル名ルールを決める
  • フォルダ名ルールを決める
  • 追加時のチェックリストを作る
  • GLBの容量目安を決める
  • 512 / 1K / 2K の使い分けを決める

推奨:

  • 通常は1K以下
  • スマホ表示で重い場合は512
  • ポリゴン数は20,000以下を目安にする

9. マネタイズ設計

目的: Artariumの雰囲気を壊さず、継続的に植物や展示要素を追加できる収益モデルを作る。

やること:

  • 無料で遊べる範囲を決める
  • 有料植物パックの単位を決める
  • 額縁・展示室テーマの課金範囲を決める
  • 広告を入れるかどうか決める
  • サブスクリプションを導入するか検討する
  • 価格帯を仮決めする
  • App Store / Google Play の課金方式を確認する

優先案:

  • 無料 + 追加植物パック
  • 無料 + 額縁・展示室カスタム課金
  • 将来的に月額プラン

優先度 低

10. 背景選択機能

目的: 額装時に背景も選べるようにする。

現在: 背景選択は無効。

将来案:

  • 暗い展示室
  • 金色の光
  • 石材背景
  • 水面背景
  • 植物ごとの専用抽象背景

注意:

  • 名画そのものを背景にしない
  • 植物と額縁が主役になるようにする

11. 作品詳細画面

目的: コレクション内の作品をより深く鑑賞できるようにする。

やること:

  • 作品名
  • 説明
  • 育成にかかった歩数
  • 完成日
  • 額縁タイプ
  • 成長過程

12. 成長履歴

目的: 植物が育った過程を振り返れるようにする。

やること:

  • Stage到達日を保存する
  • 各Stageのスクリーンショット風表示を検討する
  • コレクションから成長過程を見られるようにする

13. 通知

目的: 歩くきっかけを作る。

やること:

  • 今日の歩数が少ない時の通知
  • 開花が近い時の通知
  • 新しい植物を選べる時の通知

注意:

  • 通知は控えめにする
  • 美術館らしい文体にする

見送った案

再提案を防ぐための決定記録。

  • 作品画像の保存（完成プレートの「画像を保存」ボタン） — 2026-07-10 ユーザー判断で削除。空・水面・植物をプレート付きPNGに合成する機能だった。共有・ギフト系の導線を作る際は別の形で再検討する。
  • 作品詳細モーダルへの「記録」表示（S-2の残項目: 育成歩数・完成日・ステージ到達日タイムライン） — 2026-07-14 ユーザー判断で見送り。詳細モーダル自体（額装3Dの回転鑑賞・プレート）は実装済みで、データ（completionSteps / completedAt / stageReachedAt）も保存継続中のため、表示したくなったら小さな追加で再開できる。
  • 今日の習作（毎日1枚、その日の天気と光のシーンを自動で写し取り「習作帳」に集める）— 2026-07-10 に試作し、同日のユーザー評価で不採用。試作コードは削除済み。開花までの中日（1作品約10日）の継続動機づけ自体は未解決の課題として残る。

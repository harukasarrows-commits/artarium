## 1. プロダクト概要

| 項目 | 内容 |
|---|---|
| プロダクト名 | Artarium - 名画の庭 |
| コンセプト | 「歩くほど、絵は育つ」— 名画をモチーフにした植物を歩数で育て、開花したら額装して自分だけの美術館に収蔵する |
| 形態 | 現在: Web PWA（モバイルファースト）。将来: Expo / React Native によるiOS・Androidアプリ |
| コア体験 | ①毎日歩く → ②植物が6段階で成長 → ③60,000歩で開花（点灯式演出） → ④額縁を選んで額装 → ⑤コレクションで鑑賞 |
| 差別化 | 健康管理アプリの「数字」ではなく、美術館のような情緒的・鑑賞的な成果物に歩数を変換する |

## 2. 対象ユーザーと利用動機

- 美術館・アート鑑賞が好きな20代後半〜50代
- 散歩・歩数習慣を楽しく続けたい人（派手なゲームUIや競争要素が苦手な層）
- 植物・花・インテリアが好きな人

重視する体験: 毎日少しずつ進む / 開花時の達成感 / コレクションを眺める満足感 / 無課金でも基本体験が成立する

## 7. 制約・前提

- **技術制約**: Web単体ではiOS/Androidの歩数を直接読めない（DeviceMotionは画面点灯中のみ・精度限定）。ここが Web PWA のままでは越えられない壁で、M-3 の判断に直結する。
- **データ制約**: 保存先は localStorage のみ。容量・消失リスクを許容した設計（コレクションは再生成可能なパラメータのみ保存し、画像は保存しない方針が合理的に機能している）。
- **デザイン制約**: 「ダークギャラリー」トークン（CLAUDE.md）が正。ゲーム的な派手さ・強い課金誘導・実在作家名の表示は禁止。英語ラベルには必ず日本語を併記。
- **運用制約**: 新規ファイル追加時は sw.js の CACHE リスト追加、版数アップは「内容生成後」、配置値の焼き込みは意図したキーのみ（CLAUDE.md 鉄則1〜7）。

## 8. 主要ユーザーストーリー（受け入れ基準つき）

1. **散歩好きの会社員として**、日々の歩数が美しい植物の成長に変わってほしい。なぜなら数字だけの歩数計は続かないから。
   - 受け入れ基準: アプリを開くと今日の歩数が反映され、ステージが上がる瞬間に点灯式が再生される。
2. **アート好きとして**、完成した植物を額装して自分の美術館に並べたい。なぜなら「集めて眺める」満足感が続ける理由になるから。
   - 受け入れ基準: 開花後に額縁を選べ、コレクションに作品名・作者名（自分の名前）付きで並び、拡大して鑑賞できる。
3. **忙しい日でも**、アプリを数秒開くだけで庭の空気（天気・時間帯・季節）を感じたい。
   - 受け入れ基準: 起動するだけで現実の天気・時刻と連動したシーンが表示される。操作は不要。
4. **完成の記念に**、作品を画像として手元に残したい。
   - 受け入れ基準: 完成プレートから美術館プレート付きPNGを保存できる。
